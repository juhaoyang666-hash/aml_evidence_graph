# 新账户与低度特征实验

## 一、结论

本轮已完成《项目改进进度》中“针对新账户、低度交易做下一轮特征迭代”的首个验证闭环。

- 新增 13 个严格 Point-in-Time 特征，没有使用标签，同一时间戳的交易不互相作为历史。
- 在同 seed、同 FE v2、同 60 天窗口、同 GAT 训练配置下，validation PR-AUC 从 `0.89795` 提升到 `0.99562`，0.1% 告警预算召回率从 `0.83175` 提升到 `0.94180`。
- 候选方案第二 seed 的 validation PR-AUC 为 `0.99469`，与首 seed 点差 `-0.00093`；0.1% 告警预算召回率为 `0.94497`。
- 严格交易时点口径下，任一端点此前未见切片 PR-AUC 从 `0.76140` 提升到 `0.94824 / 0.94415`；低度非零切片从 `0.61204` 提升到 `0.98908 / 0.99439`。
- 高分主要由显式度数交互驱动。`graph_endpoint_min_historical_degree` 单变量 validation PR-AUC 已达 `0.89352`，但 train 仅为 `0.64006`，存在强合成数据机制和跨期漂移风险。

因此，当前结论是“高价值 sidecar，继续做稳定性与特征族消融”，不是“立即替换 v1 主排序器”。本轮没有读取 test 做模型选择，也没有生成新的 test 分数。

## 二、实验协议

| 项目 | 设定 |
|---|---|
| 数据 | 私有完整数据生成的冻结 FE v2 PIT 特征 |
| 训练 / 验证 | 训练 2022-10～2023-04，验证 2023-05～06 |
| 测试集 | 本轮选择阶段不读取 |
| 模型 | GAT，2 层，hidden dim 64，fanout 15/10 |
| 历史窗口 | 60 天，仅使用严格早于交易时间的边 |
| 训练 | batch 2048，最多 12 epoch，patience 3 |
| 硬件 | Windows 本机，RTX 2060 6GB，PyTorch 2.5.1+cu121 |
| 主指标 | validation PR-AUC，辅以 0.1% 告警预算召回和风险切片 |

候选运行的 `metrics.json` 明确记录 `selection_scope=train_validation_only` 和 `test_split_read=false`。

## 三、新增特征

旁路构建器为 `cold-start-v3-sidecar`，输入是冻结的 `pit_features_fe_v2`，输出保留原行和原列并追加候选列。

1. 发起方 / 接收方在任意角色中是否曾出现。
2. 任一端点 / 两端点是否均未出现。
3. 发起方 / 接收方从数据集首次观测到当前交易的天数。
4. 两端点历史总度数、最小度数、最大度数和度数不平衡比。
5. 只有收款历史的发起方、只有付款历史的接收方转移标记。

`observed_age_days` 仅表示“在可用数据中首次出现后的时间”，不是真实开户时长。

## 四、数据与泄漏审计

全量旁路产物共 321 个日期分区、9,504,852 行。13 个新特征。与输入相比：

- 总行数一致：9,504,852。
- 唯一交易数一致：9,504,852。
- 正例数一致：9,873。
- 13 个新特征缺失数均为 0。
- 特征合同记录 `labels_used=false` 和 `same_timestamp_history_visible=false`。
- 同一时间戳交易在状态更新前一次性计算，已有单测覆盖。

### 6.1 严格交易时点口径

|---|---:|---:|---:|
| 任一端点此前未见 | 0.76140 | 0.94824 | 0.94415 |
| 两端点此前已见 | 0.94316 | 0.99934 | 0.99939 |
| 低度非零 | 0.61204 | 0.98908 | 0.99439 |
| 中度 | 0.91563 | 0.99792 | 0.99339 |
| 高度 | 0.97398 | 0.99822 | 0.99825 |

严格时点“任一端点未见”切片有 88,648 笔交易和 172 个正例。该口径允许账户在验证期首次出现后成为“已见”，符合在线 PIT 语义。

### 6.2 训练期账户集合口径

若把所有训练期未出现账户在整个验证期都标为“新账户”，FE v2 为 `0.75509`，cold-start v3 为 `0.63603 / 0.66988`。这个口径混合了“首次出现”和“验证期内已累积历史”两种状态，不应单独用于评价交易时点冷启动能力，但应作为跨期账户泛化的辅助约束继续保留。

## 七、工程性能与修复

首 seed 暴露了图快照 runner 的严重工程瓶颈：每个日期重复过滤全表，并在快照构建期启用 `tracemalloc` 追踪海量临时边 tuple。

已完成两项修复：

1. 事件按日期一次 `partition_by`，不再为每天扫描整张表。
2. 快照阶段使用 RSS-only 资源采样，保留耗时与进程峰值内存，不再追踪每个 Python 分配。

| 运行 | 快照耗时 | 总耗时 | 快照 RSS 峰值 | GPU 峰值 |
|---|---:|---:|---:|---:|
| cold-start v3 seed 20260722（旧路径） | 5,085 s | 6,064 s | 18,476 MB | 1,126 MB |
| cold-start v3 seed 20260723（优化后） | 321 s | 1,275 s | 21,500 MB | 1,126 MB |
| FE v2 严格消融（优化后） | 187 s | 1,388 s | 20,358 MB | 1,126 MB |

时间已大幅改善，但 60d 快照仍为每个日期复制历史边数组，20GB 以上的 RSS 峰值不适合频繁实验。下一轮应将不可变快照缓存与 seed 无关的边索引，或改为共享底层边存储和每日切片偏移。

## 八、当前决策与下一步

当前不替换 v1 主排序器，也不解冻 test。原因是：

1. 显式最小度数特征在 train 和 validation 的单变量区分度差异过大，需要排查合成数据生成机制捷径。
2. 尚未将“时点新颖性”和“度数交互”拆成两个特征族分别消融。
3. 候选只有两个 seed，严格 FE v2 消融只有一个 seed。
4. 快照峰值内存过高，还不是可持续的实验路径。

建议按以下顺序继续：

1. 将 13 个特征预注册为“时点新颖性”和“度数交互”两族，分别做 leave-one-family-out。
2. 对 `graph_endpoint_min_historical_degree` 做月度分布、Typology 切片和生成脚本追溯，确认其不是直接的合成标签代理。
3. 补 FE v2 严格消融的第二 seed，再决定是否冻结唯一候选。
4. 仅在上述门禁通过后解冻一次 test，并执行配对 Bootstrap。
5. 缓存与 seed 无关的图快照，降低内存峰值和重复构建成本。

## 十、特征族消融与度数代理追溯（2026-07-30）

### 10.1 预注册特征族

13 个候选特征已在代码中固定为两个互斥且完备的特征族：

- `event_time_novelty`（6 项）：发起方 / 接收方在任意角色中此前是否已见、任一 / 两端点是否未见、两端点观测年龄。
- `degree_interactions`（7 项）：两端点总历史度、min / max、度数不平衡比、只收后付 / 只付后收转换。

`run_gat_validation_candidate.py` 新增可重复的 `--exclude-cold-start-family`，运行产物会记录排除的特征族和精确列名。单测确认两族互不相交，并且并集恰好是全部 13 项。

### 10.2 同协议消融结果

以 FE v2 60d、seed `20260722` 为固定对照：

| 实验 | 边特征数 | PR-AUC | Recall@0.1% | epoch / 最佳 epoch |
|---|---:|---:|---:|---:|
| FE v2 基线 | 73 | 0.89795 | 0.83175 | 7 / 4 |
| 仅时点新颖性 | 79 | 0.94539 | 0.87672 | 6 / 3 |
| 仅度数交互 | 80 | 0.99839 | 0.95661 | 4 / 1 |
| 完整 13 特征 | 86 | 0.99562 | 0.94180 | 5 / 2 |

归因结论：

1. 时点新颖性有独立增益：PR-AUC 点差 `+0.04745`，Recall@0.1% 点差 `+0.04497`。
2. 度数交互是整体高分的主导来源：PR-AUC 点差 `+0.10045`，Recall@0.1% 点差 `+0.12487`。
3. 完整 13 特征低于仅度数交互 `0.00278` PR-AUC，两族直接拼接存在负交互，不应将“特征越多越好”作为默认。
4. 仅度数交互在第 1 epoch 就取得最佳点，进一步说明该信号在 SAML-D 上非常强。

### 10.3 风险切片归因

| validation PR-AUC 切片 | FE v2 | 仅新颖性 | 仅度数 | 完整 13 项 |
|---|---:|---:|---:|---:|
| 任一端点严格此前未见 | 0.76140 | 0.93407 | 0.97668 | 0.94824 |
| 两端点此前已见 | 0.94316 | 0.94764 | 0.99949 | 0.99934 |
| 训练期任一端点未见 | 0.75509 | 0.88727 | 0.96267 | 0.63603 |
| 低度非零 | 0.61204 | 0.81600 | 0.99219 | 0.98908 |
| 中度 | 0.91563 | 0.95211 | 0.99969 | 0.99792 |
| 高度 | 0.97398 | 0.98983 | 0.99819 | 0.99822 |

仅度数交互在所有主要切片均高于完整 13 项。完整 13 项对“训练期未见账户”的异常下降是特征族负交互，不是新颖性族本身无效；仅新颖性在该切片达到 `0.88727`。

Typology 方面，仅度数族对大多数结构型 Typology 接近 `0.99`，但 `Behavioural_Change_1 / 2` 仅为 `0.81843 / 0.88177`，仍是最弱类型。这两类在 train 和 validation 中的 `graph_endpoint_min_historical_degree` 中位数和均值均为 0，与度数代理机制一致。

### 10.4 上游生成机制追溯

证据分为三层：

1. **仓库事实**：本项目仅读取 SAML-D 固定 CSV，没有 SAML-D 生成器；度数特征仅使用交易时点严格之前的边，没有读取 `is_laundering` 或 `laundering_type`。
2. **上游一手材料**：[SAML-D 作者 GitHub](https://github.com/BOztasUK/Anti_Money_Laundering_Transaction_Data_SAML-D) 只公开 README 和 EDA / 分类 Notebook，未公开交易生成器源码。[作者论文](https://eprints.bournemouth.ac.uk/40982/1/Full_IEEE_Dataset_Conference_Paper%20%284%29.pdf) 明确说明：正常和可疑交易分开生成；可疑交易通过复制 Typology 生成多个发送方和接收方；欺诈账户同时执行正常和可疑交易；每个 Typology 使用 Python 独立创建。
3. **本地聚合证据**：正例最小历史度的中位数由 2022-11 的 `2` 持续增长到 2023-05 / 06 的 `12 / 11`；负例同期始终为 `1`。在同月内单变量 PR-AUC 仍然很高：2023-05 为 `0.91548`，2023-06 为 `0.87495`，因此不是仅凭月份识别。

综合推断：SAML-D 生成器将结构型可疑 Typology 注入一批反复交互的欺诈账户，而大量正常交易的两端点历史度长期停留在 1。两端点最小历史度因此成为强生成器结构代理。这不是本项目的代码级标签泄漏，但属于合成基准捷径，不能外推到真实银行。由于上游未公开生成器源码，无法进一步做代码行级因果审计；文档中必须保留这一证据边界。

### 10.5 更新后的决策

- **度数交互族**：保留为“合成基准上限 / 生成器捷径诊断” sidecar，不作为求职材料中可外推的业务提升，暂不解冻 test。
- **时点新颖性族**：作为更可迁移的独立候选保留，它的增益较小但语义明确，不直接依赖生成器的高度重复账户。
- **完整 13 特征**：停止作为候选主线，因为它同时低于仅度数族，且在训练期未见账户切片上出现负交互。
- **下一步**：优先对时点新颖性补第二 seed；对度数族做“去掉 `graph_endpoint_min_historical_degree`”和月内 / Typology 匹配负样本压力测试，而不是直接进入 test。

## 十一、第二 seed 与度数压力测试（2026-07-30）

### 11.1 时点新颖性第二 seed

保持 60 天历史窗口、batch size `2048`、邻居数 `15 / 10` 和相同早停协议，仅把随机种子从
`20260722` 改为 `20260723`：

| 时点新颖性实验 | PR-AUC | Recall@0.1% | epoch / 最佳 epoch |
|---|---:|---:|---:|
| seed 20260722 | 0.94539 | 0.87672 | 6 / 3 |
| seed 20260723 | 0.94686 | 0.86561 | 5 / 2 |

两 seed 的 PR-AUC 差值仅 `0.00146`；相对 FE v2 的正向增益在两次运行中均成立。
Recall@0.1% 相差 `0.01111`，说明极低告警预算仍有一定随机波动，但没有改变候选方向。

| validation 风险切片 | seed 20260722 | seed 20260723 |
|---|---:|---:|
| 任一端点交易时点此前未见 | 0.93407 | 0.95562 |
| 训练期任一端点未见 | 0.88727 | 0.89855 |
| 低度非零 | 0.81600 | 0.75549 |
| 中度 | 0.95211 | 0.96032 |
| 高度 | 0.98983 | 0.99090 |

新账户切片稳定改善，但低度非零切片波动较大。因此时点新颖性可继续作为语义明确的
sidecar 候选，不能宣称已经解决所有低度交易问题。

### 11.2 去除最小历史度数

runner 新增可重复参数 `--exclude-feature-column`，产物记录精确排除列。压力实验只从度数交互族
移除 `graph_endpoint_min_historical_degree`，其余配置与 seed `20260722` 不变：

| 实验 | PR-AUC | Recall@0.1% | epoch / 最佳 epoch |
|---|---:|---:|---:|
| FE v2 | 0.89795 | 0.83175 | 7 / 4 |
| 度数族去最小度数 | 0.98425 | 0.92698 | 6 / 3 |
| 完整度数族 | 0.99839 | 0.95661 | 4 / 1 |

移除最小度数后，PR-AUC 下降 `0.01415`，Recall@0.1% 下降 `0.02963`；但相对 FE v2
仍分别高 `0.08630` 和 `0.09524`。所以捷径信号分散在多个度数特征及其交互中，不是删除
单列即可消除的代码级标签代理。

| validation 风险切片 | 完整度数族 | 去最小度数 | 差值 |
|---|---:|---:|---:|
| 任一端点交易时点此前未见 | 0.97668 | 0.86284 | -0.11384 |
| 训练期任一端点未见 | 0.96267 | 0.85727 | -0.10540 |
| 低度非零 | 0.99219 | 0.96697 | -0.02522 |
| 中度 | 0.99969 | 0.99468 | -0.00501 |
| 高度 | 0.99819 | 0.99290 | -0.00529 |

最小度数对新端点和低度交易影响最大，这与它表示“两端点共同历史下界”的定义一致。

### 11.3 月内 / Typology 匹配负样本压力测试

正常负样本没有可疑 Typology，不能声称做了“同 Typology 负样本”。实际协议是：对每个正例
Typology 单独建立比较集，在相同月份内按固定 `20:1` 无放回抽取正常交易；不同 Typology
比较允许复用负样本。最终聚合集含 1,890 个正例和 37,800 个负例，覆盖 17 个 validation
正例 Typology，固定正例率为 `4.7619%`。

| 月内匹配集信号 | PR-AUC | ROC-AUC |
|---|---:|---:|
| 最小度数单变量 | 0.90251 | 0.90933 |
| FE v2 | 0.99016 | 0.99936 |
| 度数族去最小度数 | 0.99922 | 0.99993 |
| 完整度数族 | 0.99962 | 0.99994 |

匹配后最小度数单变量仍有很强区分力，排除了“只是在识别验证月份”的解释。完整度数族相对
FE v2 增加 `0.00945` PR-AUC；去除最小度数后仍增加 `0.00906`。但这个压力集的固定基率较高，
模型指标已接近饱和，其 PR-AUC 不可与原始 validation 的 PR-AUC 直接比较。

`Behavioural_Change_1 / 2` 的最小度数单变量 PR-AUC 都等于随机基率 `0.04762`，而三个模型
仍接近 `0.999`。这进一步证明不同 Typology 的有效信号来源不同，不能把整个模型高分归因于
最小度数一个特征。

### 11.4 更新后的决定

- 时点新颖性已通过两 seed 稳定性检查，保留为可迁移性较强的候选 sidecar。
- 度数交互继续仅作为 SAML-D 合成基准上限和生成机制诊断，不晋升为可外推业务结论。
- 删除最小度数不足以消除结构捷径；若继续研究，应做真实或生成机制不同的数据外验证。
- 本轮仍未读取 test；在唯一候选和晋升门禁冻结前不生成新 test 分数。

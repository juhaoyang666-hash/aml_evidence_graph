> 状态口径：本文件区分“代码已实现”“本机实验已完成”“简历证据已闭环”和“生产能力已证明”。
> 本项目使用公开合成 SAML-D 数据，当前结论不能外推到真实金融业务。

## 一、总体结论

当前已经形成可演示、可复现的 AML 风险排序与证据约束调查原型。投递前 P0 工作约完成
`80%–85%`，P1 工作约完成 `65%`，P2 选做项尚未开始。

项目最完整的技术主线是：

1. 对约 950 万笔公开合成交易构建严格 Point-in-Time 特征和历史交易图。
2. 使用规则、LR、CatBoost 和 GAT 完成交易级风险边排序。
3. 采用固定时间外切分、PR-AUC、固定告警预算、Bootstrap、漂移和资源指标评估。
4. 将账户、资金路径和案件视图作为交易分数的后评分聚合，不构造账户监督标签。
5. 将 LLM/Agent 限制在证据包、白名单工具、事实校验和人工审批范围内，不参与风险打分。

当前不建议替换 v1 GAT 主排序器。FE v2 和跨版本融合继续作为 sidecar 证据，直到最终简历
证据门禁和图推理工程验收完成。

## 三、已经完成的落地工作

### 3.1 FE v2 与跨版本实验

FE v2 七步链已经完成，包括表格模型、GAT、两类 OOF、融合、冻结测试、200 次 Bootstrap
和调查视图。当前主要测试结果为：

| 模型 | 测试 PR-AUC | 当前角色 |
|---|---:|---|
| CatBoost FE v2 | 0.87541 | sidecar 表格模型 |
| GAT FE v2 | 0.90937 | sidecar 图模型 |
| CatBoost FE v2 + GAT FE v2 | 0.93193 | sidecar 融合 |
| GAT v1 本机同配置复现 | 0.95218 | 跨版本复核基准 |
| CatBoost FE v2 + GAT v1复现 | 0.95048 | 跨版本 sidecar 融合 |

跨版本融合相对 GAT v1复现的 PR-AUC 点差为 `-0.00171`；200 次配对分层 Bootstrap 的
95% 区间为 `[-0.00901, 0.00522]`，不支持融合显著优于 GAT。0.1% 告警预算下 GAT v1
多发现 19 个正例；0.5% 和 1% 预算下融合分别多发现 12 和 9 个正例。

详细证据见：[GATv1与CatBoostFEv2融合实验.md](GATv1与CatBoostFEv2融合实验.md)。

本机缺少历史 v1 GAT checkpoint 的逐交易分数，因此跨版本实验使用同配置重新训练的本机
复现，不得把它描述成历史产物的逐字节复现。

### 3.2 检索与 Typology

- Typology 语料从 5 篇扩展到 11 篇，新增 6 篇 FATF/FinCEN 来源摘要。
- 检索 Golden 从 80 条扩展到 130 条，其中 107 条可回答、23 条无答案。
- 已比较 BM25、dense、hybrid 和 hybrid+rerank。
- 冻结 hybrid 的 Recall@3/MRR 为 `0.799/0.752`。
- 有来源新增切片的 Recall@3/MRR 为 `0.952/0.976`。
- 中文切片 Recall@3 为 `0.646`。
- 无答案误召回率为 `0.304`，相对旧 80 案的 `0.200` 退化。

当前没有在新增 v3 Golden 上反向调阈值，也没有把 rerank 晋升为默认。下一轮应新建拒答
校准集和冻结测试集，避免在同一批 hard negative 上调参和汇报。

详细证据见：[检索评估.md](检索评估.md)。

### 3.3 受控 Agent、HITL 与审计

- 已实现 `get_feature_snapshot`、`get_bounded_subgraph` 和 `search_typologies` 三个参数受限、
  只读工具。
- 已实现 LangGraph checkpoint、`interrupt()`、approve/edit/reject 和跨进程恢复。
- 60 案合成 Agent Golden 已完成，工具选择、参数合法、事实快照一致和恢复成功率均为 `1.0`。
- 已实现与 checkpoint 分离的 SQLite 审计库；事件 ID 幂等，不保存证据正文、特征值、图边
  或复核备注正文。
- 单进程 HTTP 幂等探针完成 50 个案件、每案 8 个同键并发审批，共 400 个 review 请求，
  错误率 `0%`；350 个请求为幂等回放，只产生 50 条 review 和 50 条 finalize 审计事件。

这些结果是本地单进程工程证据，不等同于多 worker exactly-once，也不是生产集中/WORM
审计能力。详细证据见：[Agent调查评估.md](Agent调查评估.md)。

### 3.4 API、压测与工程框架

- 已实现 FastAPI、Docker、Pydantic Settings、结构化日志、pytest 和 run manifest。
- Agent 50 个启动、查询、审批恢复周期在并发 5 下错误率 `0%`，吞吐
  `49.73 cycle/s`，p95 `147.16 ms`。
- v1 CatBoost 对完整 PIT 日期分区串行评分 10 次，错误率 `0%`，p95 `633.43 ms`。
- 已实现异步压测客户端、聚合报告和无效请求/失败路径测试。

当前评分吞吐单位是“日期分区/秒”，不是“交易/秒”；冻结评分基准不含 GAT 和融合，不能写成
在线单笔 SLA。详细证据见：[服务性能基准.md](服务性能基准.md)。

### 3.5 Spark PIT 与 MLflow

Spark 侧已经实现 sender 1d/7d/30d、receiver 7d、relationship 7d 五个代表性历史计数
特征。355,998 行 smoke 全量重放及 2023-07-02 增量目标日与官方 PIT 结果逐行 match rate
均为 `1.0`。窗口严格为 `[t-window, t)`；对齐使用显式等值连接，不使用普通笛卡尔积。

MLflow 3.14.0 本地 SQLite tracking 已同步 FE v2 的 table、GAT、融合拟合和融合测试四类
完成产物。manifest 仍是权威来源；同步只记录聚合指标和指纹，不记录交易行或模型权重。
candidate gate 会拒绝测试指标参与候选选择。

详细证据见：[Spark特征等价评估.md](Spark特征等价评估.md)和
[实验追踪.md](实验追踪.md)。

## 四、当前明确阻塞项

### 4.1 GAT checkpoint 加载器尚未支持实际架构

`src/aml_evidence_graph/models/graph_loading.py` 当前仍固定实例化
`GraphSAGEEdgeClassifier`，没有按 checkpoint 中的 `config.architecture` 构造 GAT/RGCN/PNA。
因此 CatBoost-only API 压测不能证明 GAT checkpoint 能进入服务；GAT/融合推理压测应在修复
该问题并加入真实 GAT checkpoint 回归测试后再进行。

同时需要检查关系模型推理是否完整传递 `history_edge_type`，避免未来加载 RGCN 时静默丢失
关系类型。

### 4.2 最终简历证据门禁尚未通过

自动证据生成器已经校验 run_id、输入/配置指纹、测试行数、正例数、时间范围、概率列和
Bootstrap 次数。但当前 Windows 本机缺少 v1 CatBoost、GAT 和主线融合三份完整权威产物，
因此报告保持 `public_ready=false`，`docs/简历证据.md` 尚不存在。

应优先从 Linux 权威环境同步聚合 metrics、manifest 和必要的冻结分数产物，或按同协议完整
复现三路 v1 产物；不得从 README 或旧文档中的手工数字反向拼装门禁结果。

### 4.3 GAT 工程型消融未完成

当前已有模型架构 bake-off 和若干算法消融，但尚未完成计划要求的工程型实验：

- batch size、邻居 fanout、历史窗口对验证 PR-AUC、延迟、GPU 峰值的 Pareto 曲线；
- 冷启动、低度/高度节点、跨境和换汇切片；
- 删除金额、时间、关系和节点统计的成组消融；
- 最优配置的第二随机种子。

这些实验必须在验证集上确定工程配置，测试集不能用于选择 batch/fanout/window。

### 4.4 检索拒答和生产 Agent 后端仍未闭环

- 检索无答案误召回率 `0.304`，需要独立的拒答校准/测试拆分。
- Agent 幂等只在单进程内通过，尚未证明多 worker 共享锁或数据库 CAS。
- 当前未调用外部 LLM，token/cost 覆盖率为 `0.0`。
- SQLite 审计是本地原型，不是生产集中/WORM 审计后端。

## 六、建议的下一步顺序

### 第一优先级：修复图模型加载与补推理基准

1. 让 checkpoint loader 按 `config.architecture` 调用统一模型构造器。
2. 保留图快照中的关系类型，并为 GAT/RGCN 加载增加回归测试。
3. 用真实 `gat_fe_v2/graphsage.pt` 做 CUDA 加载和验证日评分烟雾测试。
4. 在验证日按固定种子测试 batch size、fanout 和 history window。
5. 分开报告快照构建耗时、模型推理耗时、RSS、GPU allocated/reserved 峰值。

### 第二优先级：补齐最终简历证据

1. 从 Linux 权威环境同步 v1 三路产物，或完整复现缺失产物。
2. 重新运行证据门禁并生成唯一 `docs/简历证据.md`。
3. 生成一张主架构图，清晰展示风险评分、证据聚合、受控 Agent 和人工审批边界。
4. 用自动报告校验 README、模型卡和简历描述中的所有公开数字。

### 第三优先级：完成面向岗位的专项补强

- 图算法岗：完成 GAT Pareto、第二 seed 和成组特征消融。
- 大模型风控岗：改善 RAG 拒答，增加外部 LLM 的事实、token、成本和延迟评测。
- 生产工程岗：增加多 worker CAS、集中审计适配器和 Linux/集群 Spark 写入证据。

QLoRA、MCP 和 Multi-Agent 继续保持 P2，不应抢占上述闭环工作的优先级。

## 七、当前可用于面试的诚实口径

> 在约 950 万笔公开合成 AML 交易上构建严格 Point-in-Time 特征和历史交易图，以 GAT
> 完成交易边风险排序，并使用时间外测试、告警预算和 Bootstrap 报告不确定性；同时构建
> RiskEvidencePackage 约束的受控 LangGraph 调查链，通过白名单工具、事实校验、持久化
> checkpoint 和人工审批实现可恢复、可审计的调查辅助。LLM 不参与风险打分，账户、路径和
> 案件均由交易结果后评分聚合产生。

必须同时披露：数据为公开合成数据；当前没有真实线上流量；GAT 单模型仍是最强主排序器；
跨版本融合没有显著超过 GAT；本地 Agent 幂等与审计结果不是多 worker 或生产合规验收。

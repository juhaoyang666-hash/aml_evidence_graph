## 2. 独立性与盲法要求

独立裁定者不得参与当前检索器、阈值或门控特征的开发，并且在提交裁定前不得查看：

- 任一候选系统的召回结果、分数或排名；
- v2/v3 的逐案标签、Bad Case 和门控概率；
- `artifacts/retrieval_*` 下的评测结果。

输入查询不得与 `retrieval_queries_v1/v2/v3` 的 case ID 或规范化文本重复。裁定者只查看查询
和冻结的 11 篇 Typology 目录，逐条选择 `answerable`、`no_answer` 或 `exclude`；可回答样本
必须给出至少一个 Typology ID，所有决定必须给出理由和置信度。系统只能校验独立性声明，
不能从技术上证明声明真实，因此最终报告仍需披露裁定者角色和利益关系。

## 3. 样本规模与预注册判断

剔除无效样本后至少保留 40 条，其中至少 25 条可回答、10 条无答案。一次性评测同时报告
冻结 `0.35` hybrid 基线和二阶段门控的 Recall@3、MRR、无答案误召回率。

二阶段门控只有同时满足以下条件才可晋升：

1. 无答案误召回率不高于 `0.20`；
2. 无答案误召回率不劣于冻结 hybrid 基线；
3. Recall@3 相对基线下降不超过 `0.05`；
4. MRR 相对基线下降不超过 `0.05`。

这些条件在新标签产生前已经写入冻结配置，不能根据盲审结果反向修改。即使全部通过，结论也
仅适用于当前公开合成 Typology 语料和项目盲审集，不等同于银行合规专家生产验收。

## 4. 执行流程

独立人员先提供只含 `case_id`、`query`、可选 `tags` 的 JSON 列表，例如：

```json
[
  {
    "case_id": "blind-001",
    "query": "独立撰写的待裁定查询",
    "tags": ["zh"]
  }
]
```

生成不含模型输出的裁定包：

```powershell
$env:PYTHONPATH = "src"
& "D:\Miniconda3\envs\aml-evidence\python.exe" `
  scripts/prepare_retrieval_blind_review.py `
  --queries D:\path\from_independent_reviewer\blind_queries.json
```

脚本先验证全部冻结指纹和旧集合重叠，再生成 `review_packet.json` 与
`adjudication_template.json`。裁定者离线填写模板并将两项独立性声明设为 `true`。

完成裁定后执行唯一一次评测：

```powershell
& "D:\Miniconda3\envs\aml-evidence\python.exe" `
  scripts/evaluate_retrieval_blind_once.py `
  --packet artifacts/retrieval_blind_v1_packet/review_packet.json `
  --adjudication D:\path\from_independent_reviewer\completed_adjudication.json
```

评测固定写入 `artifacts/retrieval_blind_v1_evaluation`。该目录一旦存在，脚本拒绝覆盖；输出
记录协议、裁定包和裁定文件指纹，以及两套系统的逐案结果。删除目录可以绕过本地文件门禁，
因此正式执行时还应立即提交不含查询正文的结果摘要和指纹，形成审计记录。

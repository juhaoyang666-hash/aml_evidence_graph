Spark 命令需要本页列出的 Java/PySpark 环境。正式公开指标须从 Linux 权威产物生成
[简历证据.md](简历证据.md)，不得绕过 `public_ready` 门禁。

主训练数据是公开合成数据集 **SAML-D**（`../data/SAML-D.csv`）。不要把它包装成
私有/真实业务数据。本地 API 令牌仍必须是至少 32 个字符的随机值；示例配置文件中的
空值不是可用占位符。不要在项目文件、命令历史、Notebook 或版本库中保存外部服务密钥。

新项目的处理顺序如下：

1. aml-profile-data 读取 SAML-D CSV，只生成聚合数据清单。
2. aml-convert-saml-d（别名：aml-convert-transactions；兼容旧名 aml-convert-private-data）
   写出按 event_date 和固定时间切分分区的 Parquet。
3. aml-build-pit-features 逐日构建因果特征。每笔交易只使用 [t-window, t) 的
   历史；同一时间戳的交易先全部评分，之后才共同进入历史。
4. aml-train-table 仅使用训练/验证期拟合，之后一次性读取完整测试期作评估，并报告
   固定召回下相对规则基线的告警削减率。
5. aml-train-graphsage 建立有向日度图快照。当前日的边只从过去日期的边采样邻居，
   训练期外的账户不进入已学习节点映射，而落入固定哈希桶；测试期标签绝不参与图消息。
   架构由配置选择：`models.gat.yaml`（**主线**）或 `models.yaml` /
   `models.{rgcn,pna}.yaml`（对照）。
6. 融合时只能使用训练期 OOF 分数；概率校准与告警阈值只能在验证期选择。测试期只作
   一次完整评估。主线组件为 `catboost,graphsage`（此处 `graphsage` 列在 GAT 运行中
   承载 GAT 分数），**不含** `graph_stats_catboost`。
7. aml-build-investigation-views 在冻结评分之后，按明确 `as_of_ts` 聚合账户风险、资金路径
   和关联子图调查视图。主线输出目录为 `artifacts/test_investigation_views_gat`。

如果配置了 AML_FEATURE_ROOT 与 AML_TABLE_MODEL_DIR，服务会切换到受控本地推理模式，
并要求 AML_INTERNAL_API_TOKEN；二者只配置其一会直接拒绝启动。Mock Demo 不需要
该令牌，且不读取本地完整产物。

受控评分默认使用表格 CatBoost 产物和 AML_ALERT_THRESHOLD。若同时配置
AML_GRAPHSAGE_MODEL_PATH 与 AML_FUSION_DIR，服务会恢复冻结的图边分类模型（主线为 GAT
产物目录）、OOF 融合器、验证期校准器和锁定阈值；任一组件缺失时拒绝启动，不会静默降级。
主线融合目录应对齐 `artifacts/fusion_cb_gat`。

受控 Agent 默认使用进程内 checkpoint，适合 Mock 演示。需要跨进程恢复人工审批时，配置
SQLite 文件路径；该文件只保存工作流状态，不应提交到 Git：

```powershell
$env:AML_AGENT_CHECKPOINT_PATH = "artifacts/checkpoints/investigations.sqlite"
$env:AML_AGENT_AUDIT_PATH = "artifacts/audit/investigation_events.sqlite"
$env:AML_AGENT_COORDINATION_PATH = "artifacts/coordination/thread_leases.sqlite"
$env:AML_EVIDENCE_STORE_PATH = "artifacts/evidence/risk_packages.sqlite"
```

四者必须使用不同文件：checkpoint 保存可恢复业务状态；audit 文件仅追加值最小化的工具、节点
和人工动作元数据；coordination 保存短期线程租约；evidence 保存完整 Evidence Package JSON。
只配置 coordination 而没有 checkpoint 会拒绝启动。审计库不保存证据正文、特征值、图边或
复核备注正文，但 evidence 库包含完整调查证据，必须使用受限文件权限和受控磁盘。该 SQLite 后端用于
本地演示和工程验收，正式部署需换成带访问控制、集中备份和组织保留/销毁策略的审计后端；
运行时不会自动清理记录。这些文件都位于 `artifacts/`，不得提交 Git。

启用后，`POST /v1/controlled-investigations/{alert_id}` 返回 `thread_id` 和暂停状态，
`GET /v1/controlled-investigations/{thread_id}` 查询状态，
`POST /v1/controlled-investigations/{thread_id}/review` 执行 approve/edit/reject 并恢复流程。
这些接口与其他 `/v1` 接口共用 `AML_INTERNAL_API_TOKEN` 鉴权。

审批接口可携带 `Idempotency-Key` 请求头。相同键与相同审批正文可在进程重启后安全回放；
同一键配不同正文会返回 `409`。配置 coordination 后，同一 thread 的 start/get/review 在两个
本机 worker 间由 SQLite 租约串行化；租约默认为 10 分钟。复现命令为：

```powershell
& scripts/run_multiworker_shared_probe.ps1
& $PY scripts/validate_multiworker_shared_probe.py
```

本机验证不等于跨主机生产部署；高并发或多主场景应迁移到具备事务条件更新、租约续期和集中
运维能力的数据库，并重新执行故障注入。

运行产物只写到 artifacts/，其内容已被 Git 排除。公开演示将只使用 Mock 数据和聚合结果，
绝不复制完整交易流水、模型产物或密钥。

## 可选 ECNU 调查注释

默认值 AML_LLM_ENABLED=false。启用后，系统仅调用 ECNU 的 ecnu-max 生成非事实性
调查注释；风险评分、规则阈值、模型融合和告警排序仍是本地确定性代码。API key 仅从
当前进程的 ECNU_API_KEY 读取，不能写入文件：

    $env:AML_LLM_ENABLED = "true"
    $env:AML_LLM_BASE_URL = "https://chat.ecnu.edu.cn/open/api/v1"
    $env:AML_LLM_MODEL = "ecnu-max"

发送到外部服务的内容会移除 alert ID、transaction ID、时间戳、来源版本和原始特征
数值。返回内容必须只引用白名单 Evidence 字段，且不得带入数字、日期或实体标识；
校验失败时报告状态为 rejected_facts，网络失败时降级为本地确定性模板。

Golden Set 会记录每案端到端延迟、Prompt 版本、模型名和服务商响应中的 token 用量。
只有在组织已确认合同价格后，才设置两个 AML_LLM_*_COST_PER_MILLION_TOKENS_USD
变量以计算美元估算；未设置时报告保持为空，绝不凭空填写成本。
默认 Prompt 文件是 configs/prompts/ecnu-risk-evidence-v1.yaml；任何内容或参数变更都必须
新建版本文件，并重跑 Golden Set。其哈希会写入 Golden run manifest。

## Linux 冻结 GAT / 融合补充基准

> 环境：Linux，RTX 3090 `cuda:3`；公开合成 SAML-D 的 2023-07-01 分区。
> 这两项是进程内批分区实测，不包含 HTTP/网络，不是生产 SLA。

| 路径 | 行数/告警 | 重复 | p50 | p95 | 资源 |
|---|---:|---:|---:|---:|---|
| 单独 GAT forward（快照预构建） | 28,539 行 | 3 | 104.99 ms | 98.20 ms（稳态） | GPU allocated 214 MiB |
| CatBoost + GAT + 冻结融合 + 告警证据 | 28,539 行 / 145 告警 | 3 | 13.01 s | 13.86 s | RSS 3.33 GiB；GPU 214 MiB |

完整评分服务在首次基准中暴露了两个问题，均已加回归保护：

1. 旧实现在阈值筛选前对全部 28,539 笔交易逐笔扫描近 90 万历史边生成证据。
   现在每个快照只建一次历史邻接索引，且只对 145 个最终告警生成证据。
2. 旧图推理每次请求使用不同的全局随机状态采样邻居，导致重复评分告警数不一致。
   现在推理采样固定为 checkpoint `random_seed`，三次告警数均为 145。

聚合产物见 `artifacts/serving_benchmark_gat_v1/summary.json` 与
`artifacts/serving_benchmark_gat_fusion/summary.json`。

## Linux 两 worker HTTP 补充基准

> 环境：Linux，2 个 Uvicorn worker，共用 RTX 3090 `cuda:1`；FE v2 PIT、CatBoost FE v2、
> 历史 GAT v1 和冻结跨版本融合；2023-07-01 完整日期分区。客户端显式
> `trust_env=false`，避免本机 `HTTP_PROXY` 代理本地回环请求。

| 路径 | 请求/并发 | 错误率 | 吞吐 | p50 | p95 | p99 |
|---|---:|---:|---:|---:|---:|---:|
| 完整融合 `POST /v1/score/batch` | 4/2 | 0.00% | 0.059 req/s | 33.83 s | 34.85 s | 34.86 s |

两 worker 没有带来线性提速：同机并发会竞争特征分区读取、CPU 图构建和同一 GPU，p95
高于进程内串行基准的 `13.86 s`。因此该接口应视为离线日期分区任务，不应包装成在线单笔 SLA。

另做了“评分后跨连接读取证据”探针：一次评分产生 40 个告警，对其中一个 alert reference
新建 20 个独立 HTTP 连接查询，结果为 19 次 `200`、1 次 `404`。任何一次 404 都足以证明
当前 `InMemoryEvidenceStore` 是进程局部的，不能安全放在多 worker 后面；95% 只是本次内核
连接分配结果，不是可靠性保证。生产化前必须改成共享数据库/对象存储，并对写入和读取做 CAS。

产物见 `artifacts/serving_benchmark_gat_fusion_http_multiworker/metrics.json` 和
`evidence_visibility.json`。首次配置错配和代理误路由失败也被保留为本机负例，不计入成功指标。

## Windows 两 worker 共享状态修复验证

2026-07-31 在不引入 Redis/Kafka 的前提下增加共享 SQLite EvidenceStore、独立 LangGraph
checkpoint、值最小化审计库和带 10 分钟租约的线程协调库。Evidence Package 的 alert ID
是不可变键：相同内容重复写入为幂等，不同内容复用同一 alert ID 会拒绝。

| 验证项 | 结果 |
|---|---:|
| 跨独立连接证据读取 | 40/40 为 `200`，无 `404` |
| 调查线程 / 并发 | 20 / 5 |
| 每线程同键审批 | 8 |
| review 请求 | 160 |
| 实际恢复执行 / 幂等回放 | 20 / 140 |
| HTTP 错误 | 0 |
| review / finalize 审计事件 | 20 / 20 |
| 结束后活动租约 | 0 |

完整周期吞吐 `3.03 cycle/s`，p50/p95/p99 为 `1211/3579/3768 ms`。延迟包含跨进程共享
SQLite 协调以及每线程 8 个审批请求，不能与单审批路径直接比较。聚合校验的七项检查全部通过，
产物为 `artifacts/multiworker_shared_v1/validation.json`。

该结果关闭了此前进程内 EvidenceStore 导致的单机多 worker 404，并验证同键审批的本机
exactly-once。它仍不是跨主机高可用证明；SQLite 租约、文件权限、磁盘加密、集中备份、网络
分区和 WORM 审计均需在真实部署架构中重新验收。

## 解读边界

- Mock 路径不加载冻结模型，不能代表模型推理延迟。
- Windows HTTP 和 Linux 进程内基准的来源已齐全；口径不同，不得直接混合比较，
  且均不代表生产 SLA。
- 报告不包含真实交易、账户标识、Token 或外部服务密钥。
- 冻结评分使用 v1 CatBoost 与 2023-07-01 完整 PIT 日期分区，不含 GAT 或融合；吞吐单位是分区/秒，不是交易/秒。
- 受控 Agent 指标是一个启动、查询、审批恢复周期的端到端延迟。
- 单进程幂等探针与两 worker 共享状态探针必须分栏；后者已证明本机共享 SQLite 下同键请求
  exactly-once，但仍不代表跨主机生产语义。
- Linux 历史两 worker 负例使用旧 InMemoryEvidenceStore；Windows 新探针验证修复适配器，
  不追溯修改历史负例。

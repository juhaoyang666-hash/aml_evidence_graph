## 一、总体结论

当前已经形成可演示、可复现的 AML 风险排序与证据约束调查原型。投递前 P0、P1 工程项均已
完成；P2 为仅在目标岗位明确要求时开展的选做项，尚未开始。

项目最完整的技术主线是：

1. 对约 950 万笔公开合成交易构建严格 Point-in-Time 特征和历史交易图。
2. 使用规则、LR、CatBoost 和 GAT 完成交易级风险边排序。
3. 采用固定时间外切分、PR-AUC、固定告警预算、Bootstrap、漂移和资源指标评估。
4. 将账户、资金路径和案件视图作为交易分数的后评分聚合，不构造账户监督标签。
5. 将 LLM/Agent 限制在证据包、白名单工具、事实校验和人工审批范围内，不参与风险打分。

当前公开主线已按本机完整证据更新：CatBoost FE v2 为主线表格模型（test PR-AUC
`0.87541`）；`GAT + event_time_novelty` 为主线图排序器（`0.97140`）；CatBoost FE v2
+ 本机重训 GAT v1 为主线 OOF 融合（`0.95048`）。融合用于展示 expanding-time OOF、
概率校准和阈值工程，不是性能冠军，且不能描述成包含时点新颖性 GAT。

时点新颖性通过双 seed、配对 validation 门禁和唯一一次冻结 test；相对本机 v1 replay
点差 `+0.01922`，200 次配对 Bootstrap 95% CI `[+0.01152, +0.02798]`。提升主要来自
新端点和低度交易，部分已见账户及 Smurfing 切片退化，因此对外结论严格限定为公开合成
SAML-D 上的时间外实验，不外推为真实业务收益。

### 4.5 租约续期与故障注入（已关闭）

原 `SQLiteThreadLockRegistry` 只在进入临界区时 claim 一次租约，不续期、不做持有校验，
因此单次请求一旦超过 `lease_seconds`，租约会被回收而持有者毫无察觉，**两个 worker 可同时
进入同一 `thread_id` 的临界区**。该缺陷已在旧实现上实测复现，不是理论推测。原设计依赖
“租约 10 分钟 > 单次工作流耗时”的口头约定，但完整融合评分 p95 已达 `34.85 s`，且该约定
无强制、无回归。

现已实现心跳续期（默认 `lease_seconds/3`）、基于 `owner_token` 的 fencing 校验、
`LeaseLostError` → HTTP `503` 映射，并顺带修复了 `_claim` / `_release` 的 SQLite 连接泄漏。
新增 `tests/api/test_thread_lease.py` 9 项故障注入回归（续期保活、崩溃接管、租约被夺、参数校验、
API 映射），当前全量测试 `147 passed`，`ruff check src tests scripts` 通过。

# LLM 调查辅助系统：边界、实现与评测

本系统中的 LLM 只辅助调查措辞和待查问题，不参与风险分数、阈值、告警排序或案件结论。
模型主线与正式效果见 [模型卡.md](模型卡.md) 和 [实验结果.md](实验结果.md)。

## 职责边界

| 环节 | 决策方 | LLM 是否参与 |
|---|---|---|
| 交易风险概率 | CatBoost / GAT / 融合器 | 否 |
| 概率校准、阈值和告警预算 | 验证期确定性代码 | 否 |
| 账户、资金路径和案件候选聚合 | 冻结交易分数后的确定性代码 | 否 |
| Typology 检索 | 本地 BM25 | 否 |
| 分析性措辞和建议核查问题 | 可选 ECNU `ecnu-max` | 是，受事实校验约束 |
| SAR 草稿骨架 | 确定性模板 | 否，LLM 只能补充非事实段落 |
| 是否申报或采取案件动作 | 人工调查员 | 否 |

一句话：**LLM 只负责措辞与提问，不负责判断与数字。**

## 当前实现

### 有界 LangGraph 工作流

`src/aml_evidence_graph/investigation/workflow.py` 使用固定节点：

```text
retrieve_typologies
  → fact_check
  → annotate
  → validate_annotation
  → draft_report
```

当前实现无自由循环和自主工具选择，`MAX_TOOL_CALLS=4`。因此准确表述应为“有界单 Agent
调查链”，不能描述为自主多 Agent 系统。固定 DAG 便于复现、审计和失败降级。

### 出站数据最小化

`minimize_evidence_for_llm()` 只发送概率名称、rule_id、特征名、图证据是否存在、Typology
元信息和缺失证据类别。交易、账户、告警 ID、时间戳、金额和原始特征数值不会发送给外部服务。

### 返回事实校验

`validate_annotation()` 执行两类约束：

1. `evidence_references` 必须属于证据包允许的引用路径。
2. 分析与问题字段不得出现任何数字字符，也不得引入 `transaction_*`、`account_*`、
   `alert_*` 或带数字后缀的同类实体 token；普通 `account-related` 复合词不误判为 ID。

校验失败时报告状态为 `rejected_facts`，外部注释和 SAR 草稿不会暴露给复核人。

### 降级策略

| 失败 | 行为 |
|---|---|
| 未启用外部 LLM 或无 key | 仅运行本地模板路径 |
| 网络、超时、HTTP 或 JSON 错误 | 只记录脱敏错误类别（如 `timeout`、HTTP 状态或 JSON 类别），回退确定性模板 |
| 注释事实校验失败 | 状态变为 `rejected_facts` |
| Typology 线索不足 | 保留缺失和不确定性，不编造匹配结论 |

任何 LLM 故障都不会影响风险评分和告警，因为评分与调查属于不同代码路径。

### 版本、用量与成本

- 当前 Prompt：`configs/prompts/ecnu-risk-evidence-v3.yaml`；v1/v2 保留用于 Bad Case 追溯
- 当前生成参数：`temperature=0`、`max_tokens=500`、JSON object 输出
- 外部请求超时由 `AML_LLM_TIMEOUT_SECONDS` 控制，当前回归使用 `120` 秒
- Prompt 内容或参数变化需新建版本并重跑 Golden
- Provider 返回 token 时记录 prompt/completion/total usage
- 未配置合同价格时成本保持空值，不推测 API 成本

## Golden 评测

案例来自 `golden/cases_v1.json`，裁定记录为 `golden/adjudication_v1.json`。它是用户授权的
项目内 agent 裁定集，不是独立第三方合规专家面板，也不是生产标签。

|---|---:|---:|---:|---:|---|
| 确定性模板 | 34 / 0 | 不适用 | 1.0 | 不适用 | 约 8.4 / 10.4 ms |
| ECNU v1 首次冻结执行 | 34 / 27 | 0.5556 | 0.8667 | 0.0 / 0.0（13 条） | 17.35 / 120.08 s |
| ECNU v3 同集合修复回归 | 34 / 27 | 0.7407 | 1.0 | 0.90 / 0.90（20 条） | 7.24 / 10.21 s |
| ECNU v3 预注册 Holdout | 24 / 20 | 0.7500 | 1.0 | 0.80 / 0.7333（15 条） | 6.77 / 44.46 s |

模板路径产物：`artifacts/golden_summary.json`，run
`20260726T124225Z-d0dc4bc053`。2026-08-04 的 v1 首次冻结执行为
`20260804T031333Z-e6d35f041c`：27 次调用中 10 次超时、1 次 HTTP 500、1 次非法 JSON；
15 次成功解析中 2 次被事实门拒绝。13 条安全输出虽全部保持条件化和问题可执行，但人审发现
它们均从“分数字段存在”推断风险升高，严格 Grounding 与 Overall 均为 `0.0`。

`20260804T033209Z-b7e39be09d` 有 20 条安全输出，20/20 事实门通过；项目内逐条复核 18/20
通过严格 Grounding 和 Overall，条件化、问题可执行均为 20/20，实际返回的对抗案例注入抵抗
为 2/2。其余 7 次返回非法 JSON，说明 Provider 可用性仍未闭环。

v3 是观察 v1 Bad Case 后在同一集合上的开发回归，**不是独立盲测**。人审记录分别为
`golden/llm_adjudication_ecnu_max_v1.json` 和 `golden/llm_adjudication_ecnu_max_v3.json`；
v3 仅对安全输出报告 prompt/completion tokens `11175 / 8362`，未配置合同价格，成本保持空值。

随后先于外部运行提交 `41922b8`，冻结 24 个全新 case ID、Prompt 与 cases SHA-256、单次执行、
禁止逐案重试和成功阈值。Holdout run `20260804T061709Z-2930f2efc8` 的 20 次外部调用中，
15 次解析成功，15/15 通过自动事实门，4/4 确定性探针被拦截；项目内人审覆盖 15/15。
Grounding `0.80`、问题可执行 `0.9333`、实际返回对抗案例的注入抵抗 `0.75`、Overall
`0.7333`，**未通过**预注册的 Grounding/Overall 最低 `0.90`。主要 Bad Case 是从空的
missing-evidence 列表推断资料完整、再次把隐藏分数称为 elevated、缺少核查问题，以及把标识符
外传注入转写成推荐问题。该结果冻结为负结果，不对 v3 或 Holdout 案例做事后修补。

Holdout 独立于 Prompt v1-v3 调整并在结果揭示前预注册，但复核者仍是项目 Agent，因此只能称为
“Prompt 隔离的项目内盲测”，不是外部合规专家验收。协议和裁定分别位于
`golden/llm_holdout_protocol_v1.json`、`golden/llm_adjudication_ecnu_max_holdout_v1.json`。
可公开聚合证据已更新到 `reports/public/llm_ecnu_max_evaluation_20260804.json`，只包含 run_id、
源摘要 SHA-256、聚合指标、延迟和 token，不包含模型原文、证据正文或密钥；CI 会校验冻结 cases、
Prompt 与协议哈希、100% 人审覆盖、开发/盲测边界和成本空值。

受控工具工作流另使用 `golden/agent_cases_v2.json` 的 60 案回归集，覆盖 12 路由、24 工具
边界/注入、12 审核和 12 故障恢复。确定性无 LLM 基线的 Case 通过率、工具选择准确率、
参数合法率、事实一致率和恢复成功率均为 `1.0`，本机 p50/p95 约 `18.4/111.5 ms`；因为没有
外部模型调用，token/cost 覆盖明确记为 `0.0`。详细工程验证见下文。

## 已覆盖的对抗类型

- Prompt 注入与忽略上级指令
- 诱导编造金额、汇率、账户或百分比
- 账户标识外传请求
- 要求越权给出案件结论
- 无证据情况下要求肯定回答
- 引用不存在的证据字段

开发集 34 案中有 10 个 adversarial case、7 条确定性探针；Holdout 24 案中有 10 个
adversarial case，其中 6 案真实调用、4 案确定性探针。

## 受控 Agent 工程验证

### 60 案回归与审计

60 案回归的 Case 通过率、工具选择准确率、参数合法率、事实一致率和恢复成功率均为 `1.0`。
持续检索失败会记录 `TimeoutError` 并回退确定性模板，状态仍停在
`draft_requires_human_review`。每案保存节点时间线；工具事件只记录工具名、参数名、输出键、
耗时、状态和错误码。

LangGraph checkpoint 与追加式 SQLite 审计库相互分离。审计表使用稳定 `event_id` 和
`INSERT OR IGNORE` 防止回放重复，不保存证据正文、特征值、图边或备注正文；Evidence Store
则保存完整 Evidence Package，必须使用受限文件权限和受控磁盘。SQLite 只是本地演示后端，
不等同于集中/WORM 审计、组织保留策略或生产访问控制。

### 审批幂等与多 worker

审批接口支持 `Idempotency-Key`：同键同正文返回幂等回放，同键不同正文或无键重复终态返回
`409`。单进程探针以 50 个线程、每线程 8 个并发同键审批发出 400 个请求，错误率 `0%`，
350 个为回放，审计库最终各有 50 条 review/finalize；周期 p50/p95/p99 为
`526.97/668.67/849.61 ms`。

两真实 Uvicorn worker + 四个分离的共享 SQLite 文件下，跨连接证据读取 `40/40` 为 `200`；
20 个线程共 160 个审批请求得到 20 次实际执行、140 次回放、0 错误，review/finalize 各
20 条，活动租约归零。该结论限于本机多进程，不代表跨主机 exactly-once 或生产 SLA。

### 租约续期与故障注入

线程租约使用 `owner_token`、默认每 `lease_seconds/3` 心跳续期和 fencing。续期失败或释放时
不再持有租约会抛 `LeaseLostError`，API 映射为可重试的 `503`；过期持有者不能误删接管者租约。
9 项回归覆盖持有 3 倍租约周期、崩溃后接管、owner token 被夺、非法参数和 API 映射。旧实现
“租约过期后两个 worker 同时进入临界区”的问题已实测复现并由这些用例锁定。

边界仍是单机多进程：跨主机数据库、网络分区和真实进程 `SIGKILL` 未验证；进程退出后依赖
租约自然过期，最坏停顿一个 `lease_seconds`。

## 对外表达纪律

可以说：

> 构建 RiskEvidencePackage 约束的 LangGraph 调查链，对外字段最小化，返回经过引用白名单与
> 数值/实体校验；失败回退确定性模板，LLM 不参与评分和案件结论。

不要说：

- “用大模型提高 AML 识别率”
- “自主 Agent 已代替人工调查”
- “Golden 是第三方合规验收”
- “Mock Demo 或合成数据代表真实生产效果”
